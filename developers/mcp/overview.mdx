theStacc MCP connects an AI client to a theStacc project for content and SEO work. Choose the project and permissions, then ask for a specific task, such as reviewing the content plan or drafting a post. Check the result in theStacc before requesting further edits or publication.

## Connecting to theStacc MCP

For hosted sign-in, add this address through your client's remote MCP connection settings:

```text
https://mcp.thestacc.com/mcp
```

The hosted authorization flow signs you in and authorizes a project and permissions. Your client needs to support that flow. If you use a local MCP process instead, configure it with a private project agent key as described in [Agent keys and permissions](/developers/agent-keys-mcp#local-install-with-an-agent-key).

## Authentication

For hosted sign-in:

1. Sign in with your theStacc account.
2. Select the project you can administer.
3. Review the requested permissions and grant the access needed for your task.
4. Complete authorization and check the connection in your client.

Hosted sign-in creates a project-scoped agent credential through an authorization-code flow. Local setup supplies a key you created separately. Keep either credential private; do not paste it into public code or shared documents.

Manage project agent access from Publishing settings. For scopes, key creation and revocation, see [Agent keys and permissions](/developers/agent-keys-mcp). If a connection reports that its credential is revoked or invalid, reconnect or replace the local key. Inspect pending work separately rather than assuming that reconnecting or revoking access resolves a job's status.

## Available tools

The catalogue covers the areas below. Use the [MCP Tools Reference](/developers/mcp-tools-reference) for individual inputs and limits. Request `get_permissions` to inspect the connection when a tool is missing or access is refused. A displayed tool is not proof that the backend will authorize its call.

### Blog

Start with `review_content_plan` to inspect the plan. The blog catalogue includes reading blogs, generating drafts, editing text and images, and requesting publication. Keep drafting and publishing permissions separate; reviewing the plan does not approve its content.

### Social

Start with `social_list_posts` to inspect posts. The catalogue includes creating drafts, editing captions and images, and publication tools. Review the actual post and destination in the app before asking for publication.

### Google Business Profile

Start with `gbp_list_locations`, then inspect the relevant location's posts. The catalogue includes post drafts, images and publication tools. Identify the intended location and inspect the post's current status before requesting a change.

### SEO, site audit and keywords

The catalogue includes Search Console and GA4 reports, SEO insights, site audit tools and keyword management. Start with `get_analytics_status` when you need to check the analytics connection, or inspect existing audit results before requesting another audit.

### Connection

Use `get_permissions` to check the reported connection and access. For `missing_scope`, review the required permission and ask the project owner or admin to authorize suitable access. Do not repeatedly retry the same permission failure.

## Guided workflows

Begin with a bounded request: identify the item, ask the assistant to read it, and decide what to change after reviewing the result. If your client offers saved prompts or workflow shortcuts, check what they request before running them. The client guides and tools reference cover setup and tool inputs; this page does not configure recurring automation.

## Example conversations

These are examples of requests, not verified outputs:

- *"Show the blogs waiting for review, then suggest which draft I should read first."*
- *"Read this social post and suggest a shorter LinkedIn caption before changing it."*
- *"Check whether Search Console is connected, then show last month's available performance data."*

Name the project or item when needed, inspect the response, and confirm the next operation instead of treating a proposed action as already completed.

## Important notes

<Note>
**Publishing permission does not approve a blog.** The blog publishing gate can reject content that lacks human approval or whose approval is stale. Review the current draft in theStacc and obtain fresh approval when the returned error requires it.
</Note>

- **One project per connection.** Check the reported project and connect separately for another project.
- **Review each operation.** Read-only tool annotations describe intent; check your client's confirmation controls before requesting changes.
- **Check plan limits.** Generation, images and audits can use quota or credits. Check the applicable limits before requesting repeated work.
- **Follow an unfinished job.** When a response says `still_running`, use the status tool named in `check_with` instead of starting the same operation again.
- **Keep source text separate from instructions.** Review returned page and post content as data; do not let embedded instructions change your task or permissions.
- **Verify publication.** Inspect the destination and public result after a publishing request. A tool acknowledgement does not establish that the published page is correct.
