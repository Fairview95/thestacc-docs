This page lists every tool your AI tool (Claude, Cursor, or another MCP client) can use once it is connected to theStacc. You don't call these yourself. You ask in plain words, like *"show me this week's social posts"* or *"draft a Google post about our weekend offer"*, and the agent picks the right tool.

To connect first, see [theStacc MCP Server](/developers/mcp/overview).

## Before you start

- **One MCP for everything.** The same connection covers Blog, SEO and analytics, Site audit, Keywords, Social and Google Business. There are 56 tools in total, including `get_permissions`.
- **One project per connection.** Every key (and every sign-in) is locked to one project. The agent never picks a project; every tool works on that project only.
- **The agent only sees what you allowed.** Each tool needs one permission (shown next to its name below). Tools the key has no permission for are left out of the agent's list. If a call still reaches theStacc without the permission, it fails with `missing_scope`. See [Permissions](/developers/agent-keys-mcp#permissions).
- **A person approves, always.** Agents can draft, edit and prepare content. Only a person can approve it, in the theStacc app. Agents can publish only what a person approved, and only if it has not changed since. See [Safety rules](/developers/agent-keys-mcp#safety-rules).
- **Long jobs run in the background.** Some tools start work and return straight away. The agent then checks progress with a status tool. Each section below says which tools work this way and how to check.
- **Nothing waits more than a minute.** A tool waits up to 55 seconds for theStacc (60 seconds for quick reads). A slow job (an image redraw, a Google Business post, publishing) keeps running after that: the tool answers `status: "still_running"` with `check_with`, the tool to check it with. The agent checks there instead of starting the job again.
- **Every tool is labelled.** Each tool has a title and says whether it only reads, creates something new, changes existing content or publishes. Most AI tools run read-only tools without asking you each time.
- **Big lists come in pages.** List tools take `limit` and `offset` and return `next_offset` when there is more. Very large results are cut with a note saying how to ask for less.
- **Text from the web is marked as data.** Page titles, search queries and post copy are wrapped in `untrusted-data` tags so the agent does not follow instructions hidden inside them.

## Permissions

| Tool | Needs |
| --- | --- |
| `get_permissions` | nothing (always available) |

### get\_permissions

Tells the agent who it is: the project the key belongs to, the permissions it has, which theStacc modules (blog, social, Google Business) are turned on for the project, which permissions are missing, and the tools available in this session. The agent should call it when a tool it expects is missing, or when a call fails with `missing_scope`. It reads the permissions live, so a change you just made shows up here. It also says whether this is an older key from before permissions existed.

| --- | --- | --- |
| `review_content_plan` | `blog:read` | Planned and draft blogs plus plan details. Start here |
| `get_blog` | `blog:read` | One blog in full |
| `generation_status` | `blog:read` | Progress of a blog that is being written |
| `generate_blog` | `blog:write` | Write a planned blog |
| `cancel_generation` | `blog:write` | Stop a blog that is being written |
| `generate_more` | `blog:write` | Add 1 to 10 new planned blogs |
| `draft_from_abstract` | `blog:write` | Start a new blog from your own brief |
| `set_scheduled_date` | `blog:write` | Pick the publish date for a blog waiting for one |
| `edit_blog` | `blog:write` | Change text and SEO fields |
| `regenerate_section` | `blog:write` | Rewrite one section |
| `regenerate_image` | `blog:write` | Make a new image or edit the current one |
| `retry_failed_images` | `blog:write` | Re-run only the images that failed |
| `upload_image` | `blog:write` | Put your own image into a blog |
| `publish_blog` | `blog:publish` | Publish a blog a person approved |

### review\_content\_plan

Returns the blog list (id, title, status, scheduled date for planned and draft blogs) and the plan summary (dates, expiry, whether a new plan can start). If the plan summary can't be loaded, you still get the blog list.

- **status** (optional): only blogs in this status, for example `generated_pending_review` or `approved`.
- **limit** (1 to 200, default 50) and **offset**. `total` and `next_offset` say whether there are more.

### generate\_blog

Writes a blog that is already in your plan.

- **blog\_id** (required)
- **additional\_direction** (optional, up to 2,000 characters): extra steering, like "lead with a customer story".

Returns at once with status `generating`. Poll `generation_status` until the blog reaches **Pending Review**. A blog still waiting for a publish date can't be generated: set the date first with `set_scheduled_date`.

### generation\_status

- **blog\_id** (required)

Returns the status, a short status message, word count, images done out of the total, and any error.

### cancel\_generation

Stops a blog that is `generating` or `text_ready_images_pending`.

- **blog\_id** (required)

If text was already written, it is kept and the blog moves to Pending Review. Otherwise it goes back to `to_be_generated`. It is not picked up again automatically for its scheduled date; start it again with `generate_blog`.

### generate\_more

Adds new planned blogs with AI-picked titles and keywords.

- **count** (required, 1 to 10)

New blogs land in **Awaiting Date** and are not written until each has a publish date. The agent can set one with `set_scheduled_date`, or you can pick it in the dashboard. Your plan's remaining capacity still applies. See [Generate more (bonus blogs)](/content-seo/generate-more-bonus-blogs).

### draft\_from\_abstract

Starts a brand-new blog from the agent's own brief instead of the plan.

- **abstract** (required, 10 to 4,000 characters): what the article should cover.
- **blog\_type** (optional): for example `how_to`.

Returns a blog id that is already generating. Poll `generation_status`. It counts against your plan's article allowance like any other blog.

### set\_scheduled\_date

Picks the publish date for a blog in **Awaiting Date** (for example one added by `generate_more`).

- **blog\_id** (required)
- **scheduled\_date** (required, `YYYY-MM-DD`): today or later. Yesterday is accepted and treated as today, to allow for time zones.

The blog moves to `to_be_generated` and is written on that date. If its topic was never planned, it is planned now and the response includes the new title. This only works for blogs in Awaiting Date. To move any other blog's date, use the dashboard.

### get\_blog

- **blog\_id** (required)
- **include\_config** (optional): also return the generator's full working data. Rarely needed.

Returns the full content, title, excerpt, meta title and description, status, scheduled date and image regeneration state. The agent should read the latest version before editing.

### edit\_blog

Saves changes to a blog. Only the fields sent are changed.

- **blog\_id** (required)
- **title**, **content**, **excerpt**, **meta\_title**, **meta\_description** (all optional)
- **allow\_image\_removal** (optional): set to true only when the edit is meant to remove images.

What happens to the status:

- Editing the content of a blog in **Pending Review** moves it to **Modified - Pending Review**.
- An **Approved** or **Scheduled** blog keeps its status, but after a content edit a person must approve it again before it can be published.
- Editing a **Published** blog marks it to sync. The live site does not change until it is synced.

When sending content, the agent must keep every image from the current version. An edit that would drop images is refused with `images_would_be_removed` unless `allow_image_removal` is true. See [Blog Status Lifecycle](/content-seo/blog-status-lifecycle).

### regenerate\_section

Rewrites one section of a blog.

- **blog\_id** (required)
- **section\_html** (required, up to 100,000 characters): the exact HTML of the section.
- **tone** (0 to 100, default 50): 0 is formal, 100 is casual.
- **length** (0 to 100, default 50): 0 is shorter, 100 is longer.
- **additional\_prompt** (optional, up to 1,000 characters)
- **persist** (default true): saves the rewrite into the blog. Set false to preview only.

The response's `persisted` field confirms the save. If it is false, the section no longer matched the blog: the agent should read the blog again and place the returned HTML with `edit_blog`.

### regenerate\_image

Makes a new version of one image in a blog. **Runs in the background.**

- **blog\_id** (required)
- **image\_src** (required, up to 2,000 characters): the current image address, exactly as in the content.
- **image\_alt** (required, up to 500 characters)
- **mode**: `create` makes a new image (steered by `custom_prompt` if given). `edit` changes the current image as described in `custom_prompt` and keeps its composition. Required whenever `custom_prompt` is sent, and `edit` always needs a `custom_prompt`.
- **custom\_prompt** (optional, up to 1,000 characters)
- **style** (0 to 100, default 50): 0 is modern, 50 is abstract, 100 is realistic.
- **image\_type** (optional): `photo`, `diagram`, `infographic`, `illustration` or `brand_text`. Diagrams and infographics may carry text labels; the others are kept text-free.
- **image\_occurrence** and **image\_occurrence\_of** (optional, send both): only when the same image appears more than once.

Returns at once with status `regenerating`. The new image is swapped in 1 to 2 minutes later. Poll `get_blog` until `ai_generation_config.image_regen_status` is `success` (the new address is in `image_regen_new_url`) or `failed` (the reason is in `image_regen_error`).

### retry\_failed\_images

Re-runs image generation for **only** the images that failed in a blog, using their original prompts.

- **blog\_id** (required)

Works when the blog is `generated_pending_review`, `modified_pending_review`, `generation_failed` or `unpublished`. It can take several minutes (the tool waits up to 5). The response lists what was retried, what succeeded, what still failed, and the new status. If it times out, the work may still finish: check `get_blog` before retrying.

### upload\_image

Puts your own image (a product photo, a screenshot) into a blog instead of an AI image. It is stored in the project's asset library and converted to WebP.

- **blog\_id** (required)
- **image\_base64** and **filename**: the image as base64 plus a file name like `photo.png`. Use this with the hosted MCP.
- **file\_path**: a local file path. Only works with the local install, where the MCP runs on your own computer.
- **alt\_text** (optional, up to 500 characters)
- **placement** (default `replace`): `replace` swaps an existing image, `append` adds it at the end, `featured` sets it as the featured image (also used for social cards) without touching the body, `none` only stores it and returns an image snippet to place with `edit_blog`.
- **image\_index** (default 0): which image to replace, counting from 0.

Limits: up to 15 MB. On the hosted MCP the image travels inside the request, and requests are capped at 8 MB, so keep hosted uploads under about 6 MB. Returns the asset id, the public address and a ready `<img>` snippet. Uploading into a published blog marks it to sync.

### publish\_blog

Publishes a blog to the site connected to the project.

- **blog\_id** (required)
- **integration\_id** (optional): defaults to the active connection.

Rules:

- The blog must be **Approved** by a person in the dashboard, or the call fails with `not_approved`.
- The approval must cover the exact text being published. If the blog changed after it was approved, the call fails with `approval_stale` and a person needs to approve it again.
- A publish can be held by the SEO check (`seo_gate`) or a compliance check (`held_for_compliance`, `blocked_for_compliance`). The error lists what was found and says whether a person can override it in the app. An agent can never override a hold.

On success it returns the published address.

## SEO and analytics

All of these read data theStacc already synced from Google Search Console and Google Analytics 4. They are fast and free to call.

| Tool | Needs | What it does |
| --- | --- | --- |
| `get_analytics_status` | `seo:read` | Is Search Console / GA4 connected, last sync, reconnect needed |
| `get_search_console_performance` | `seo:read` | Clicks, impressions, CTR, position, top queries and pages |
| `get_seo_insights` | `seo:read` | Ranked to-do list: quick wins, CTR gaps, declining pages and more |
| `get_ga4_overview` | `seo:read` | Sessions, users, engagement, conversions, channels, sources |
| `get_blog_performance` | `seo:read` | Traffic and search results for each blog theStacc published |
| `get_monthly_seo_report` | `seo:read` | The monthly SEO report |

Parameters:

- `get_search_console_performance` and `get_ga4_overview`: **days** (1 to 180, default 28). Search Console data is synced daily and Google finalizes it 2 to 3 days late.
- `get_blog_performance`: **range** `28d` (default) or `90d`.
- `get_monthly_seo_report`: **month** as `YYYY-MM` (optional; defaults to the latest complete month).

If a Search Console or GA4 tool returns `not_found`, call `get_analytics_status` first: the property is probably not connected.

## Site audit

| Tool | Needs | What it does |
| --- | --- | --- |
| `run_site_audit` | `seo:write` | Start a site audit |
| `get_audit_status` | `seo:read` | Progress of an audit run |
| `get_audit_dashboard` | `seo:read` | One-call health summary |
| `get_audit_issues` | `seo:read` | Findings from the latest completed audit |
| `get_audit_finding` | `seo:read` | Full detail for one finding |
| `get_audit_pages` | `seo:read` | Crawled pages with per-page facts |

### run\_site\_audit

Starts a crawl of the project's website. **Runs in the background.** If a run is already going, you get that run instead of a second crawl. Each new run counts against the project's monthly audit allowance; `rate_limited` (HTTP 429) means it is used up. The agent should call `get_audit_status` first and not retry blindly. Poll `get_audit_status` until the status is `completed`, then read `get_audit_issues`.

### Reading results

- `get_audit_status`: **run\_id** (optional; defaults to the latest run). Returns the phase, pages crawled, and `nextPollSeconds`.
- `get_audit_issues`: filter by **stage** (`availability`, `indexability`, `discoverability`, `page_understanding`, `search_relevance`, `experience`, `ai_retrieval`), **severity** (`critical`, `warning`, `info`), **status** (`open`, `regressed`, `verifying`, `resolved`) or **search** (up to 200 characters). **page** and **page\_size** (up to 200, default 50).
- `get_audit_finding`: **finding\_id** (required).
- `get_audit_pages`: **disposition** (for example `ok`, `blocked`, `broken`, `redirected`, `noindex`) and **limit** (up to 500, default 50).

| Tool | Needs | What it does |

| `list_keywords` | `seo:read` | Keywords with volume, difficulty, intent and the blog for each (paged: `limit` up to 500, default 100, and `offset`) |
| `add_keywords` | `keywords:write` | Add 1 to 50 keywords |
| `generate_keywords` | `keywords:write` | Research and add a fresh batch |

<Warning>
A social post a person approved, or one that is already scheduled or live, is **locked** for agents. Every change fails with `approved_post_locked`. To let the agent change it, move the post back to review in theStacc first.
</Warning>

### social\_list\_posts

- **status** (optional): for example `pending_review`, `approved`, `scheduled`, `published`.
- **content\_plan\_id** (optional)
- **limit** (1 to 500, default 25) and **offset**

### social\_generate\_post

Creates a new social post with AI: caption, hashtags and image or images for the project's platforms, in your brand's style. **Runs in the background.**

- **topic** (3 to 500 characters): what the post is about, for example "our Diwali offer: 20% off until Nov 5". Creates a new post.
- **post\_id** (instead of topic): generate a post that is already planned (status to be generated, failed, missed, rejected or cancelled) now.
- **platforms** (optional, new post only): `linkedin`, `instagram`, `x`, `facebook`. Defaults to every connected platform.
- **scheduled\_date** (optional, new post only, `YYYY-MM-DD`): the earliest date. The post takes the first day from there with no other post. Defaults to tomorrow.
- **additional\_direction** (optional, up to 1,000 characters): extra steering, like "friendly tone, mention free parking".

Returns the **post\_id** with status `generating`. Poll `social_generation_status` until it is done (usually 1 to 3 minutes), then read it with `social_get_post`. The post lands in review: **you** approve it in theStacc before it is published. It counts against your plan's monthly post quota. If generation could not start (for example the plan is out of posts), the error names the post that was created so the agent does not create it twice.

### social\_get\_post and social\_generation\_status

Both take **post\_id**. `social_get_post` returns the caption, per-platform captions, first comment, hashtags, images, platforms, schedule, status and compliance check. `social_generation_status` returns whether the caption and images are ready, the image generation and edit status, and the compliance check.

### social\_edit\_post

An agent can change **only** these fields:

- **caption** (up to 10,000 characters)
- **platform\_captions**: per-platform text, like `{ "linkedin": "...", "instagram": "..." }`
- **first\_comment**: per platform
- **hashtags** (up to 60)
- **scheduled\_date** (`YYYY-MM-DD`) and **scheduled\_time** (local `HH:MM`, 24-hour)
- **allow\_content\_removal** (optional)

`platform_captions` and `first_comment` **replace the whole map**. The agent must send every platform's text (read the post first), or the others are deleted. An edit that would empty the caption or drop a platform's caption is refused with `content_would_be_removed` unless `allow_content_removal` is true. An agent can't approve, reject or change status (`approval_requires_person`), and other fields are refused with `field_not_editable_by_agent`.

### social\_regenerate\_caption

Rewrites one platform's caption in about 5 seconds and saves it. The image and status don't change.

- **post\_id** (required)
- **platform** (required): `linkedin`, `instagram`, `x` or `facebook`
- **additional\_direction** (optional, up to 500 characters)

### social\_regenerate\_image

Redraws the post's image or images from its saved design and keeps the caption.

- **post\_id** (required)
- **in\_image\_copy** (optional): the words drawn on the image (`headline`, `cta_text`, `mechanism_line`, `outcome_line`). Leave out to keep the current words.
- **slide\_content** (optional, carousels only, up to 12 slides)

Takes **30 to 90 seconds** (longer for a carousel) and returns the new image addresses. If it takes longer than about a minute, the tool answers `still_running` while the redraw continues: poll `social_generation_status` until `image_generation_status` is `success` or `failed`, then read the post. A second request while one is running is refused with `regen_in_progress`.

### social\_edit\_image

Edits an image with an instruction, like "make the background navy". **Runs in the background.**

- **post\_id** (required)
- **instruction** (required, up to 4,096 characters)
- **intent** (optional): `image` edits the picture itself, `scene` changes a carousel's layout or text.
- **slide\_index** (optional, carousels, counting from 0) or **apply\_all** (optional, every slide)

- **request\_id** (optional): send the same one when retrying the same edit, so it runs and is paid for once. Without it, retrying the same edit on the same post version reuses the running job automatically.

Returns at once with status `editing`. Poll `social_list_image_versions` until `job.state` is no longer `queued` or `running`. On success the new version's id is `candidate_revision_id`. The post's image does not change until the agent calls `social_use_image_version`.

### social\_use\_image\_version

Makes one image version the post's current image.

- **post\_id** and **revision\_id** (required)
- **expected\_updated\_at** (optional): guards against overwriting a newer change.

The post goes back to review, so a person approves the new image before it is published.

### social\_publish

Publishes or schedules a social post.

- **post\_id** (required)
- **publish\_now** (required): true sends it now, false schedules it.
- **scheduled\_for** (optional, ISO 8601 date and time) and **timezone** (optional, for example `Asia/Kolkata`)
- **platforms** (optional): only these platforms, which must already be on the post.

Works only for a post a person approved **and** that has not changed since (`not_approved` or `approval_stale` otherwise). A person's approval already schedules the post for its date and time, so the agent usually doesn't need this tool.

| `gbp_get_location` | `gbp:read` | One location's details |
| `gbp_connection_status` | `gbp:read` | Is the Google profile connected for publishing |
| `gbp_list_posts` | `gbp:read` | List a location's posts |
| `gbp_get_post` | `gbp:read` | One post in full |
| `gbp_content_plan` | `gbp:read` | When the plan expires and whether the next can start |
| `gbp_publish_status` | `gbp:read` | Refresh a post's publish result |
| `gbp_generate_post` | `gbp:write` | Write a new post |
| `gbp_regenerate_post` | `gbp:write` | Rewrite a post's text |
| `gbp_edit_post` | `gbp:write` | Change a post's fields |
| `gbp_generate_image` | `gbp:write` | Generate and attach an AI photo |
| `gbp_upload_image` | `gbp:write` | Attach your own photo |
| `gbp_remove_image` | `gbp:write` | Remove the photo |
| `gbp_publish` | `gbp:publish` | Publish an approved post to Google |
| `gbp_retry_publish` | `gbp:publish` | Retry a failed publish |

Posts live under a location. Call `gbp_list_locations` first: every other tool needs a **location\_id**, and post tools also need a **post\_id**. `gbp_list_locations` always sends the key's project, so it lists only that project's locations.

<Warning>
A Google Business post that a person approved, or one that is publishing or published, is **locked** for agents (`approved_post_locked`). Any agent change to a post means a person has to approve it again before it can be published.
</Warning>

### Reading

- `gbp_list_posts`: filter by **year**, **month** or **status** (`pending_content`, `generating`, `generated`, `generation_failed`, `copied`, `approved`, `publishing`, `published`, `publish_failed`, `rejected`). **limit** (up to 100, default 50) and **offset**.
- `gbp_connection_status`: connecting a Google profile is a person's job in theStacc. If it isn't connected, publishing fails.
- `gbp_publish_status`: refreshes the result from the publisher (`published`, `publishing` or `publish_failed` with the reason). It never sends anything to Google.

### gbp\_generate\_post

Writes a new post with AI. Counts against the plan's post quota.

- **post\_type** (required): `update`, `offer` or `event`
- **scheduled\_date** (required, `YYYY-MM-DD`)
- **topic** (optional, up to 500 characters)

### gbp\_regenerate\_post

Rewrites an existing post's text. **user\_direction** (optional, up to 500 characters). A post that is already live or publishing can't be rewritten (`post_is_live`, `post_is_publishing`).

### gbp\_edit\_post

- **title** (up to 300 characters)
- **content** (up to 1,500 characters, Google's limit)
- **cta\_type**: `learn_more`, `book`, `order`, `shop`, `sign_up` or `call`
- **cta\_url** (https), **offer\_code**, **offer\_terms**
- **scheduled\_date** and **scheduled\_time** (local `HH:MM`; an empty value resets to the location's default time)
- **allow\_content\_removal** (optional)

An agent can't change status (`approval_requires_person`). Blanking the title or content is refused with `content_would_be_removed` unless `allow_content_removal` is true.

### Images

- `gbp_generate_image`: **additional\_direction** (optional, up to 500 characters). Replaces the current image. There is a daily image limit per project.
- `gbp_upload_image`: your own **JPEG or PNG, up to 5 MB**. Send **image\_base64** with **filename** (hosted), or **file\_path** (local install only). Replaces the current image.
- `gbp_remove_image`: needs **allow\_content\_removal: true**, so a photo is never removed by accident. The text can still be published without it.

### gbp\_publish and gbp\_retry\_publish

`gbp_publish` sends an approved post to Google now. `gbp_retry_publish` retries a post whose publish failed (`publish_failed`). Both work only for a post a person approved **and** that has not changed since (`not_approved` or `approval_stale` otherwise). For offers and events the scheduled date counts as content, because Google shows it as the start date, so changing it also needs a new approval.

`gbp_publish` returns once publishing starts (status `publishing`). Check the outcome with `gbp_publish_status`.

## A typical session

1. `get_permissions` to see the project and what the key may do.
2. `review_content_plan`, `social_list_posts` or `gbp_list_locations` to see what is waiting.
3. Draft and refine: `generate_blog`, `edit_blog`, `social_generate_post`, `social_edit_post`, `gbp_generate_post`, and so on.
4. **You** review and click **Approve** in theStacc.
5. The agent publishes what you approved: `publish_blog`, `social_publish` or `gbp_publish`.
