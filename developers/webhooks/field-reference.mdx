A webhook receiver needs to distinguish a field that is missing from one that is present with `null` or an empty string. It also needs to accept different article payloads for manual publishing, scheduled publishing and **Sync**. Use the field map below to design validation and storage, then confirm your project's actual delivery shape before enabling writes.

The core article payload includes structured `ctas`. The optional `author` field depends on whether a byline has been configured or explicitly cleared. Confirm that your receiver supports those mappings before enabling them.

`excerpt_short` uses the reader-facing excerpt, then the meta description, then an empty string. It trims surrounding whitespace and limits the result to **256 characters**, including a trailing ellipsis when truncation is needed. It prefers a word boundary when one is sufficiently far into the text, but can cut a long unbroken value. Because an empty excerpt triggers its fallback, `excerpt_short` is not always a truncated copy of `excerpt`.

Where present, `published_at` is a UTC publish-time value produced with an ISO-format timestamp. Accept an explicit UTC offset such as `+00:00`; do not require a literal `Z` suffix. On an update, decide whether this delivery timestamp belongs in a modification field. Do not overwrite the original publication date just because a publish or republish delivery contains a new timestamp. Sync does not supply this field in the path described here.

Set limits from your CMS and receiver schema instead of treating typical content lengths as hard caps. Reject an unsupported value with a useful error, or document an intentional normalization policy rather than silently truncating it.

The body preparation removes the **first** inline image matching the featured-image URL, allowing a query string or fragment on that URL. It leaves the body unchanged if no match exists or no featured-image URL is supplied. Consequently, do not rely on a blanket guarantee that the hero can never appear in the body.

When supplied, `images` lists quoted `src` values extracted from the prepared body, in document order, deduplicated by the exact URL string. It does not extract lazy-loading `data-src` values. An absent alt attribute produces an empty alt string. Render or mirror the images your site needs using the [self-hosting images guide](/developers/webhooks/self-hosting-images); keep featured-image handling separate.

Scheduled publishing adds `idempotency_key` and `publish_attempt`. The scheduled key described here combines the blog ID with the stored external post ID, or `new` before an external ID exists. Repeated updates to the same external ID can share a key, so it is not a unique identifier for every separate edit. Define retry deduplication without suppressing legitimate later updates; see [idempotency and retries](/developers/webhooks/idempotency).

## Blog author

Manual publishing, scheduled publishing and Sync include the configured optional author. When no explicit author setting exists, the field is omitted. Saving a website-default reset sends `author: null`; a valid explicit selection sends its name and `Person` or `Organization` type, plus an ID when selected from the site directory. Your receiver must implement the corresponding byline update.

This illustrative author fragment represents an organization byline:

```json
{
  "author": {
    "name": "Editorial Team",
    "type": "Organization"
  }
}
```

Check property presence rather than truthiness so a deliberate null reset is handled. Author saves require a nonblank name of up to 200 characters and a `Person` or `Organization` type. A directory ID is optional; validate it against your own author records before assigning a byline.

### Website receiver checklist

1. Validate the event before validating article fields. Handle a connection test without inserting an article.
2. Upsert publication and update events using the article identity, with a documented policy for missing, null and empty values.
3. If optional author support is confirmed, map its ID or name into the site's byline model. Define what happens when an ID no longer exists.
4. Render stored names as escaped text and keep visible bylines, listing cards and article structured data consistent.
5. Refresh the relevant page or build caches after a successful update. Verify the public page instead of treating a delivery acknowledgement as proof of rendering.
6. Test your handler locally with new, updated, missing-field, null-field and repeated-delivery fixtures. Keep the authentication and deduplication policies appropriate to your integration.

Scheduled payloads include generated `jsonld`, while the manual publishing and Sync paths described here omit it. An explicit author supplies the scheduled `BlogPosting` author name and `Person` or `Organization` type. Without an explicit author, the graph falls back to an `Organization` using project or website naming before the blog author and finally `Editorial Team`. Maintain the site's visible byline and structured data from the same stored record on every update.

## Select existing site authors

Configure an optional author directory using **Author-list URL** in Custom Webhook settings. In the blog author form, selecting an **Existing website author** fills a draft; **Save author** stores the selection. Saving alone does not update the public website. The [existing website authors guide](/developers/webhooks/authors) covers directory limits, selection and receiver responsibilities.

The `ctas` list is also rendered into the prepared HTML resources section, identified by `class="fairview-cta-resources"`, before the locked footer. If you render structured links separately, remove only that resources section rather than unrelated footer content. A successful response alone does not prove that your mapping was applied; use the [response contract](/developers/webhooks/response-contract) when designing acknowledgements.
