---

theStacc MCP lets an AI tool such as Claude or Cursor work on your theStacc project for you. You can ask it to *"review my content plan and write the next blog"*, *"show me how my blogs did on Google last month"*, *"fix the caption on Friday's LinkedIn post"* or *"draft a Google Business post about our weekend offer"*. The agent does the work. You stay in charge of what gets approved and published.

One connection covers everything:

- **Blog**: plan, write, edit, add images, publish approved blogs
- **SEO and analytics**: Search Console, Google Analytics 4, SEO insights, monthly report
- **Site audit**: run an audit and read the findings
- **Keywords**: see, add and research keywords
- **Social**: read, edit and redraw posts, publish approved posts
- **Google Business**: write, edit and illustrate posts, publish approved posts

There are 56 tools in total. The full list is in the [MCP Tools Reference](/developers/mcp-tools-reference).

## Two ways to connect

| | **Sign in with theStacc** (recommended) | **Local install with an agent key** |
| --- | --- | --- |
| **Best for** | Claude, Cursor and other tools that support remote MCP servers | Tools that can only run a local MCP server |
| **What you do** | Paste one address, sign in, approve | Create a key in theStacc and paste it into your tool's config |
| **Needs** | Nothing to install | Node.js 18 or newer on your computer |
| **Address** | `https://mcp.thestacc.com/mcp` | `npx @thestacc/mcp-server` |

Both ways end up the same: a key locked to one project, with the permissions you chose, that you can revoke at any time.

## Sign in with theStacc

<Steps>
  <Step title="Add theStacc to your AI tool">
    Add `https://mcp.thestacc.com/mcp` as a remote (custom) MCP server or connector. Step-by-step instructions for each tool are in [Connect theStacc to Claude](/developers/connect-claude) and [Connect from the terminal](#connect-from-the-terminal) below.
  </Step>
  <Step title="Sign in">
    Your tool opens a theStacc page in your browser. Log in with your usual theStacc account.
  </Step>
  <Step title="Pick one project">
    You see the projects you own or are an admin of. Pick the one this tool should work on.
  </Step>
  <Step title="Choose what it can do">
    The permissions are pre-ticked with what the tool asked for. Untick anything you don't want to allow. You can only narrow the list, never add to it.
  </Step>
  <Step title="Approve">
    Click **Approve**. You are sent back to your tool, connected. Click **Deny** to cancel.
  </Step>
</Steps>

The sign-in page is valid for 10 minutes. If it expires, start connecting again from your tool to get a fresh link.

Behind the scenes, theStacc creates an agent key with exactly the project and permissions you picked. It shows up in your key list as **MCP: \<app name\>** (for example "MCP: Claude"), and you can revoke it there. The connection lasts until you revoke it; after that, the tool asks you to sign in again.

## Connect from the terminal

Copy-paste setups for tools that support remote MCP servers with sign-in. Each one opens the theStacc sign-in page described above.

**Claude Code**

```bash
claude mcp add --transport http thestacc https://mcp.thestacc.com/mcp
```

Then run `/mcp` inside Claude Code, choose **thestacc** and sign in. To make theStacc available in every project, not just the current folder, add `--scope user`:

```bash
claude mcp add --transport http --scope user thestacc https://mcp.thestacc.com/mcp
```

**Cursor**: add this to `~/.cursor/mcp.json` (every project) or `.cursor/mcp.json` (one project):

```json
{
  "mcpServers": {
    "thestacc": {
      "url": "https://mcp.thestacc.com/mcp"
    }
  }
}
```

**Codex CLI**

```bash
codex mcp add thestacc --url https://mcp.thestacc.com/mcp
codex mcp login thestacc
```

**Gemini CLI**

```bash
gemini mcp add --transport http thestacc https://mcp.thestacc.com/mcp
```

Then run `/mcp auth thestacc` inside Gemini CLI to sign in.

**Tools without remote sign-in**: use the [local install](#local-install-with-an-agent-key) with an agent key, or bridge the hosted server through `mcp-remote` (needs Node.js 18 or newer), which handles the sign-in in your browser:

```json
{
  "mcpServers": {
    "thestacc": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "https://mcp.thestacc.com/mcp"]
    }
  }
}
```

## Permissions

Every key carries permissions that decide what the agent can do. You choose them when you create a key in theStacc or when you approve a sign-in. The agent only sees the tools its permissions allow. If it tries something it isn't allowed to do, the call fails with `missing_scope` and the agent should tell you which permission is missing.

| Area | Permission (as shown in theStacc) | Technical name | What it allows |
| --- | --- | --- | --- |
| Blog | **Read posts** | `blog:read` | See the plan, blogs and progress |
| Blog | **Draft and edit** | `blog:write` | Write, edit, add images, set dates |
| Blog | **Publish approved posts** | `blog:publish` | Publish blogs a person approved |
| Social | **Read posts** | `social:read` | See posts, progress and image versions |
| Social | **Draft and edit** | `social:write` | Edit copy and schedule, rewrite captions, redraw and edit images |
| Social | **Publish approved posts** | `social:publish` | Publish or schedule posts a person approved |
| Google Business | **Read posts** | `gbp:read` | See locations, posts, plan and connection |
| Google Business | **Draft and edit** | `gbp:write` | Write, edit and illustrate posts |
| Google Business | **Publish approved posts** | `gbp:publish` | Publish posts a person approved |
| SEO and keywords | **Read SEO scores and keywords** | `seo:read` | Search Console, GA4, insights, reports, audit results, keyword list |
| SEO and keywords | **Fix SEO issues** | `seo:write` | Start a site audit |
| SEO and keywords | **Change target keywords** | `keywords:write` | Add keywords and research new ones |

Ticking a permission also ticks the ones it depends on. For example, **Publish approved posts** also ticks **Draft and edit** and **Read posts** for that area.

Three presets sit above the list:

- **Read only**: read access to Blog, Social, Google Business and SEO. Nothing can change.
- **Draft (no publishing)**: everything except the three publish permissions. **This is the default for a new key.**
- **Full access**: everything, including publishing approved posts.

**Older keys.** Keys created before permissions existed are labelled **Blog + SEO (older key)** in the key list. They keep exactly what they always had: Blog, SEO and keywords, with no Social or Google Business access. To give an agent Social or Google Business access, create a new key or sign in again, then revoke the old key.

Permission changes reach the hosted MCP within about 5 minutes. With the local install, restart your AI tool to refresh the tool list.

## One project per key

Every key, including the ones created by signing in, is locked to one project. The agent can't see or change any other project. If you run several businesses in theStacc, connect each project separately.

## Agent keys

You need an agent key for the local install. Keys created by signing in appear in the same list.

Manage keys in **Content SEO > Settings > Publishing > Agent access** (marked **Beta**). Only a project owner or admin can create, see or revoke keys.

1. Type a **Key name** (optional, up to 120 characters), for example "Cursor on my laptop".
2. Under **What this key can do**, pick a preset or tick permissions.
3. Click **Generate agent key**.
4. Copy the key (it starts with `sk_agent_`) and the config snippet. **The key is shown only once.**
5. Click **I've saved it**.

Good to know:

- **Shown once.** theStacc stores only a one-way hash of the key, so it can never show it again. If you lose it, revoke it and create a new one.
- **The list** shows each key's first characters (for example `sk_agent_AbC123••••`), its name, when it was last used, and badges for its permissions, like "Blog: read, draft, publish".
- **Revoke** stops every agent using that key straight away. It can't be undone.

## Local install with an agent key

The local install runs the MCP on your own computer with `npx`. Nothing is installed globally, but you need **Node.js 18 or newer**.

In **Claude Desktop**, open **Settings > Developer > Edit Config**. In **Cursor**, use `~/.cursor/mcp.json` or `.cursor/mcp.json`. Add:

```json
{
  "mcpServers": {
    "thestacc": {
      "command": "npx",
      "args": ["-y", "@thestacc/mcp-server"],
      "env": {
        "THESTACC_AGENT_KEY": "sk_agent_your-key-here"
      }
    }
  }
}
```

Restart the tool and ask: *"What can you do with thestacc?"* If the key is wrong or revoked, you get an `unauthorized` error.

Settings (environment variables):

| Variable | Required | What it does |
| --- | --- | --- |
| `THESTACC_AGENT_KEY` | Yes | Your agent key (`sk_agent_...`) |
| `THESTACC_API_ROOT` | No | API root for every service. Default `https://api.thestacc.com` |
| `THESTACC_API_URL` | No | The original blog address setting, still honoured. Default `https://api.thestacc.com/blog`. Social and Google Business use the same root, so older configs keep working |
| `THESTACC_TIMEOUT_MS` | No | Request timeout in milliseconds. Default 60000 (60 seconds) |

You almost never need anything except the key.

### Uploading your own images

- **Hosted (signed in):** the agent sends the image inside the request as `image_base64` with a `filename`. Requests are capped at 8 MB, so keep images under about 6 MB.
- **Local install:** the agent can also pass a `file_path` to a file on your computer.

Google Business photos must be JPEG or PNG, up to 5 MB. Blog images can be up to 15 MB with the local install.

## Safety rules

These rules are enforced by theStacc itself, not by the AI tool, so they hold whatever the agent tries.

- **Approving is always a person's job.** Agents can't approve, reject or change the status of anything, in any module. You approve in the theStacc app.
- **Agents publish only what you approved, unchanged.** An agent can publish a blog, social post or Google Business post only if a person approved it and it has not changed since. If it changed, the agent gets `approval_stale`. If it was never approved, `not_approved`. Either way, approve it again in theStacc and the agent can publish.
- **Blog: only the exact text you approved goes live.** An agent may edit an approved blog, but then it can't be published until a person approves the new version.
- **Approved social and Google Business posts are locked.** Once a person approves a post (or it is scheduled, publishing or live), agents can't change it (`approved_post_locked`). Move it back to review first if you want the agent to work on it.
- **Nothing is deleted by accident.** An edit that would remove images from a blog (`images_would_be_removed`) or delete copy or a photo from a social or Google Business post (`content_would_be_removed`) is refused unless the agent explicitly says the removal is intended.
- **Holds stay with people.** If the SEO check or a compliance check holds a publish, the agent can't override it. A person can review it in the app, where the hold allows it.
- **Changes made while the agent worked are kept.** If you edit or approve a post while the agent is working on it, the agent's change is not saved (`post_changed`) and it has to read the post again.

## When the agent reports an error

Errors arrive as `[code] message`. Here is what the common ones mean and what to do.

| Code | What it means | What to do |
| --- | --- | --- |
| `unauthorized` | The key is wrong, missing or revoked | Sign in again, or create a new key and update your config |
| `missing_scope` | The key doesn't have the permission this needs | Create a key (or sign in again) with that permission. `get_permissions` lists what is missing |
| `forbidden` | Not allowed for this project or action | Check the key is for the right project |
| `not_approved` | The content was never approved by a person | Approve it in theStacc, then ask the agent to publish |
| `approval_stale` | It changed after it was approved | Review the latest version and approve it again |
| `approved_post_locked` | A social or Google Business post is approved, scheduled or live | Move it back to review if you want the agent to change it |
| `approval_requires_person` | The agent tried to approve or change a status | Do it yourself in theStacc |
| `images_would_be_removed` | A blog edit would delete images | Ask the agent to keep the images, or confirm the removal is intended |
| `content_would_be_removed` | An edit would delete a caption, text or photo | Ask the agent to send the full text, or confirm the removal is intended |
| `post_changed` | Someone changed the post while the agent worked | Ask the agent to read it again and retry |
| `seo_gate` | The SEO check held the blog | Ask the agent to fix the listed problems, then publish again |
| `held_for_compliance` / `blocked_for_compliance` | A compliance check held the publish | Review it in theStacc. Some holds can be overridden by a person; blocked content must change |
| `payment_required` | This needs an active plan | Check billing in theStacc |
| `not_found` | The item doesn't exist in this project, or Search Console / GA4 isn't connected | Check the id, or connect Google in theStacc |
| `validation_error` | An input was missing or out of range | The message says which field |
| `too_large` | The upload is over the size limit | Use a smaller image |
| `rate_limited` | Too many requests, or a monthly allowance (like site audits) is used up | Wait and try again later |
| `upstream_timeout` | theStacc didn't answer in time | The work may still be running. Ask the agent to check before retrying |
| `upstream_error` | A temporary problem on theStacc's side | Try again in a moment |
| `network_error` | The tool couldn't reach theStacc | Check your internet connection |

## Agent key vs. Public Blog API key

theStacc has two kinds of project keys. They are not interchangeable:

| | **Agent key** (`sk_agent_...`) | **Public Blog API key** (`pk_live_...`) |
| --- | --- | --- |
| **Purpose** | Let an AI tool work on your project | Show your published blogs on a website |
| **Access** | The permissions you chose, with approval-gated publishing | Read-only, published blogs |
| **Where it goes** | Your private AI tool config, or created for you by signing in | A website or static-site build |
| **Created in** | **Agent access** | **API Access** |
| **Shown** | Once, at creation | Any time in settings |

The Public Blog API key is safe in a website because it can only read published content. The agent key can change and publish content, so keep it private. See [Public Blog API](/developers/public-blog-api).

## Security

- **Stored safely.** theStacc keeps only a hash of each key, never the key itself.
- **Keep it private.** Never put an agent key in a website, a public repo or a shared document. If a key leaks, revoke it straight away.
- **Locked down.** A key works on one project, with only the permissions you gave it, until you revoke it.
- **Sign-in is standard OAuth.** The hosted MCP uses OAuth 2.1 with PKCE and dynamic client registration. The access token it issues is a scoped agent key. There is no refresh token.
