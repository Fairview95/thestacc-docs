A blog type tells theStacc which writing format to use for an article. Choose a format that fits the reader's task, such as instructions or a comparison, then review the generated structure. The current manual dropdown contains 13 options. Planning can also produce a type that the manual dropdown and update endpoint do not currently support.

The use cases above are editorial recommendations. The labels are the current UI options; the recommendations are not promises that every label has a unique generation template or scoring rule.

## What each type produces

The writer receives the saved blog type as part of its brief. Some formats have explicit prompt instructions and mechanical structure checks. Others use general writing instructions. The [SEO Scoring Explained](/content-seo/seo-scoring) guide describes the score's purpose and limits. The thresholds below describe theStacc's own mechanical checks, not search-engine requirements.

### How-To Guide

The writing prompt asks for numbered H2 step headings, practical tips and substeps. The mechanical intent check awards its full points when it detects at least four numbered H2 headings. Use as many steps as the task needs; do not invent steps to satisfy the check. **Tutorial** uses the same mechanical branch.

### Listicle

The writing prompt asks for numbered H2 headings and scannable items. The mechanical intent check awards its full points for at least five numbered H2 headings. A useful list still needs distinct items and enough explanation to help the reader choose or act.

### Comparison

The writing prompt requires an HTML comparison table. The mechanical check is less strict: it can award full intent points for a table, at least three versus headings, or detected pros-and-cons sections. Meeting that check does not prove the comparison is complete. Review whether the criteria, values and recommendation are supported.

### Ultimate Guide

The prompt asks for broad coverage and supporting subsections. The mechanical check awards full intent points when there are at least six H2 sections and 1,500 words. Those are scoring thresholds, not an instruction to pad the article. Remove sections that repeat the same explanation or do not answer a reader's question.

### Case Study

The prompt asks for a problem-and-solution format with outcomes and metrics. Supply evidence for the case, then check that the draft accurately describes it. The mechanical check looks for numeric patterns and at least three H2 sections; it does not verify a real customer, test method or outcome. Do not publish an invented success story to fill the format.

### News & Trends

The planner can map **Industry Trends** to the saved type `news_trends`. The writer formats that value as **News & Trends**, and the mechanical scorer has a branch for it. However, this type is absent from the current manual dropdown and from the update endpoint's accepted types.

If a planned blog has this type, do not assume the editor can save it unchanged. Choose an available type deliberately or ask support about the mismatch before editing. A recent date detected by the scorer does not verify that a news claim is current.

### Beginners Guide

The current dropdown calls this **Beginner's Guide**. The prompt asks for simple language, foundational concepts, steps and an FAQ. The mechanical check awards full intent points when it detects an FAQ and at least four H2 sections. Review unfamiliar terms and examples so a new reader can follow the explanation.

### Product Review

Use this format when you have sources for the product's features and limitations. The system prompt prohibits fabricated reviews, attributed praise and testimonials. Selecting **Product Review** does not establish first-hand testing, and the mechanical intent check has no dedicated product-review branch. Describe the evidence you actually have.

### Expert Roundup

Use an expert roundup when you have identifiable sources for the perspectives being discussed. The system prompt prohibits invented quotes and attributed statements. The mechanical intent check has no dedicated expert-roundup branch, so review the attribution and substance yourself; a type label does not establish an interview or expert endorsement.

### Problem Solution

The current dropdown calls this **Problem & Solution**. The prompt asks for a focused difficulty and a response. The mechanical check looks for both problem and solution markers in headings. Headings alone cannot establish that the proposed solution works; explain the method, its limits and the evidence supporting it.

Article length depends on the brief and generation settings. The type alone does not guarantee a word count, media count or finished level of quality. Review the draft before approving it.

## How a blog type is set

A blog can receive its format during planning or through a manual edit before content is generated. The saved value is passed to the writer when generation runs. Saving a different type updates the plan field; the update endpoint does not turn that field change into a rewrite of an existing article.

### 1. Auto-assigned by the AI during planning

The planning tool asks the AI to select a category and maps that category to a saved blog type. Its category choices differ from the manual dropdown: **Industry Trends** maps to `news_trends`, while the planner's **Tips & Tricks** category maps to **How-To Guide**. Review the planned type rather than assuming every planner category matches a selectable UI label.

### 2. Chosen manually on the blog

On a blog detail page with a ready plan and no content, project editors can click **Edit Plan**, select **Blog Type**, then click **Save Changes**. The editor also saves the plan's title, description, date and keyword. Confirm those fields before saving.

Choose the type before generating the article. A saved type change alone does not alter an existing body. For content that has already been written, review the available actions in [Regenerating Content](/content-seo/regenerating-content) and preserve any copy you need before requesting a rewrite. The current update endpoint blocks plan-only edits during generation.

## When to pick each type for your goal

Start with what the reader needs to accomplish. A task suits instructions; a purchase decision needs a supported comparison; a broad subject may need a guide. Use a case study only when you have a documented case, and use a roundup only when you have sourceable perspectives.

Choose the more specific label when it helps clarify the brief. The additional **Guide**, **Review** and **Tips & Tricks** options have no dedicated branch in the checked mechanical intent scorer; they receive its neutral handling. **Tutorial** shares the How-To branch. These are implementation details of that check, not measures of how useful your article will be.

Keep articles distinct by their reader question and evidence. Changing the type on two posts with the same purpose does not, by itself, resolve duplicate coverage. Review the content plan and existing articles before adding another version of the same answer.
